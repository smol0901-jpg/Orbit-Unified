# Реестр заглушек облака (версия 5.3.2 → вернуть ближе к 10.0)

**Принцип:** ничего не удалено. Исходные обработчики остаются в `js/orbit/assistant.js`; пока `CLOUD_READY = false`, они не выполняются, а вместо них Кон коротко отвечает:
> Облако, стена, друзья, личные сообщения и расписания с push сейчас в разработке — планируем ближе к версии 10.0 (в 5.x не успеваем). Всё остальное работает как обычно.

Найти все места: поиск по `CLOUD_READY` и `CLOUD_SOON` в `js/orbit/assistant.js`.

## Что заглушено

| Правило (имя) | Фразы | «Замок»* | Исходное поведение |
|---|---|---|---|
| `cloud-sync` | облако, синхронизация, синхронизируй, выгрузи в облако | — | вход/синхронизация данных и переписки |
| `cloud-status` | статус облака, состояние синхронизации | — | строка состояния |
| `wall-post` | опубликуй…, напиши на стену…, пост на стену… | `стен` | пост на общую стену от имени агента |
| `wall-read` | что нового на стене, покажи/открой/читай стену, обучись со стены | `стен`, `облак` | чтение стены, обучение агента |
| `cfriend` | добавь в друзья…, пригласи в друзья…, найди друга… | — | поиск и приглашение друга |
| `cdm` | отправь/напиши/передай (личное) сообщение <кому> <текст> | `личн` | личное сообщение другу |
| `cron-add` | поставь/сделай/добавь/включи/запланируй задание/сценарий/cron… | `задани`, `сценари`, `cron` | расписание сценария + push |
| `cron-list` | мои расписания, список заданий, cron задания | — | список заданий |

\* **Замок** — слово, без которого правило пропускается (`return null`), чтобы обычные фразы («покажи ленту», «опубликуй релиз», «отправь сообщение Ирине») не перехватывались заглушкой.

Эти правила добавлены в начало `PRI` (порядок проверки), потому что иначе их перехватывали другие: «что взять завтра» → `pack`, «покажи стену» → `nav`, «напиши на стену» → `sms`.

Остальные места:
- Вкладка **«Облако»** в агенте (`A.panel === 'cloud'`) — при `!CLOUD_READY` показывает «в разработке».
- Действие кнопки **`cfriend`** (приглашение из карточки) — при `!CLOUD_READY` отвечает заглушкой.
- `memPush` / `trimLocalMem` не менялись: без `O.cloud` ничего не делают.
- `js/orbit/cloud.js`, `js/orbit/cron.js` **не подключены** (нет в `index.html` и в `CORE` у `sw.js`).
- Тесты: группа «Облако» в `tests/suite.js` проверяет заглушку — при возврате удалить/заменить.

## Статус (октябрь 2026)
Облако **не успели** в линейке 5.x. Развитие перенесено ближе к **10.0**. Код и миграции сохранены, заглушки обновлены.

## Чек-лист возврата при старте ~10.0
1. Применить `db/migrations/001_init.sql`, затем `002_records_sync.sql` на тестовом проекте Supabase.
2. **Исправить `cloud.js` под новую схему:** `state` и `push_sub` лежат в `profile_private` (строки с `.from('profiles').update({ state … })`, `.select('state')`, `push_sub`) — публичная таблица `profiles` содержит только `id, name, last_seen`.
3. Подключить `js/orbit/cloud.js` и `js/orbit/cron.js` в `index.html` (после `work.js`, до `assistant.js`) и добавить в `CORE` у `sw.js`.
4. Сделать экран «Облако» (адрес проекта и anon-ключ → `orbit-sb-config-v1`, вход, статус). Кнопки `tab:cloud` сейчас ведут на несуществующую вкладку.
5. В `assistant.js` поставить `CLOUD_READY = true`; решить, оставлять ли «замки» (`CLOUD_GATE`) — они защищают от ложных срабатываний.
6. Проверить конфликты правил: `cdm` и `sms` («отправь сообщение»), `wall-read` и слово «лента», `cron-add` и `remind`/`lesson-add`, `wall-post` и `sms`.
7. Написать Edge Function для cron + web-push (ключи VAPID).
8. Тесты: убрать «Облако: заглушка», добавить тесты входа, синхронизации, очереди, RLS (два пользователя).
9. Версия: `10.0.0` (или ближайший MAJOR) одновременно в `version.json`, `APP_VERSION` (`js/app.js`), имени кэша `sw.js`, `CHANGELOG.md`.
